Operating system

The workflow separates doing, reviewing, and claiming.

  1. 1

    Scope

    Define intent, risk, affected files, and evidence gaps.

    Open scoping packet
  2. 2

    Implement

    Make the smallest correct change inside the approved boundary.

    Open implementation prompt
  3. 3

    Review

    Reject scope drift, shallow tests, broken UI, or unsupported claims.

    Open review prompt
  4. 4

    Specialist review

    Use accessibility, security, testing, documentation, or release gates when relevant.

    Open specialist library
  5. 5

    Verify

    Run exact commands and disclose skipped or unavailable checks.

    Open verification script

    Claim only what is proven

    End with verified, partially verified, not verified, or blocked.

Proof rails

Verification is part of the product.

The scripts check structure, linkage, claim discipline, examples, and the 100-asset library.

Checked automatically

  • Asset metadata and dependencies
  • Public claim restrictions
  • Homepage and builder browser flows
  • Automated accessibility rules
  • ZIP extraction and integrity

What has not been verified

  • Universal workflow effectiveness
  • WCAG conformance or assistive-technology coverage
  • Security posture of generated or deployed systems
  • Performance under production workloads
  • Legal suitability for a specific adopter
